# 属于是猎杀者

MaiBot 插件。在消息真正发出去之前，按概率把「属于是 / 了属于是」清掉。

## 为什么需要它

MaiBot 会把 bot 自己的历史回复当作 few-shot 上下文回灌给模型。模型说过一次「属于是」，下一次请求里就多了一条「我自己平时就是这么说话」的示范。

于是口癖开始自我强化。光靠 prompt 约束压不住，因为示范样本每轮都躺在上下文里给模型看，你说多少次「不要这样说」都不如上下文里那一条实例管用。

这个插件挂在发送链路的最后一环，对最终可见文本做概率性清除。被清掉的部分不会进数据库，也就不会成为下一轮的示范。跑久了，上下文里自我示范的密度会被逐步稀释。

## 为什么挂在 send_service.before_send

发送链路上能改文本的地方不止一处，选这里是因为它同时管住了两件事。

出站消息进入 Platform IO 之前，这里是最后一站，此后不再被改写。

写库（`_store_sent_message`）发生在这个 Hook 之后，所以数据库里留下的也是净化后的文本。

第二件事更要紧。落库文本正是下一轮上下文的来源。只改发出去的内容而不管落库内容，等于把口癖原样喂回给下一轮的自己，治不了根。

## 安装

在 WebUI 的插件市场搜索「属于是猎杀者」安装。

手动安装的话，把仓库复制到 MaiBot 的插件目录即可。目录名不影响识别，插件靠 `_manifest.json` 认人。

## 配置

安装后在 WebUI 插件配置页可以直接改，也可以编辑插件目录下的 `config.toml`。

| 配置项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enabled` | bool | `true` | 总开关 |
| `kill_ratio` | float | `0.7` | 每处口癖被清除的概率，0.7 表示杀掉七成 |
| `patterns` | list | `["了?属于是"]` | 猎杀用正则，默认连前面的「了」一起吃棹 |
| `cleanup_text` | bool | `true` | 清除后修掉残留的开头标点与多余空白 |
| `guard_empty` | bool | `true` | 清完整条消息不再含文字时，整条回滚 |
| `max_kills_per_message` | int | `0` | 单条消息最多清几处，0 表示不限 |
| `sync_processed_text` | bool | `true` | 同步净化落库用的纯文本 |
| `dry_run` | bool | `false` | 只记录不修改，用来观察命中率 |
| `log_kills` | bool | `true` | 每清一处输出一条日志 |
| `only_groups` | list | `[]` | 只在这些群生效，留空表示全部群 |
| `skip_groups` | list | `[]` | 在这些群里跳过 |

### 几种常见的调法

**先观察再动手。** 把 `dry_run` 打开跑一两天。日志里会打印每条的命中数，以及「按 0.7 概率本应清除约 N 处」，确认命中率符合预期再关掉。

**只想在特定群用。** 把群号填进 `only_groups`，其他群完全不受影响。反过来，想在某些群放它一马就填 `skip_groups`。

**嫌杀得太狠。** `kill_ratio` 降到 0.5 或者 0.3。降到 0 等同于关闭。

**口癖不止「属于是」。** `patterns` 是正则列表，加 `"绝了"`、`"属实"` 这类都可以。多条同时命中时按左起优先匹配。

## 实际效果

下面是从连续 24 小时运行记录里摘的原文。

```
耳机一摘谁也不爱了属于是                   → 耳机一摘谁也不爱
RLHF刻进骨髓了属于是，底层总想跳出来教人做事🤔  → RLHF刻进骨髓，底层总想跳出来教人做事🤔
防御性编程拉满了属于是                     → 防御性编程拉满
习惯了属于是                             → 习惯
UI设计师梦回2018了属于是                   → UI设计师梦回2018
随插随拔属于是                            → 随插随拔
道德审查模块算是给你玩明白了属于是           → 道德审查模块算是给你玩明白
```

`习惯了属于是` 清完还剩 `习惯`，消息有内容，正常发出。

如果清完整条只剩标点，`guard_empty` 会把整条回滚，不会发出一个孤零零的问号。清到组件为空的情况也做了拦截，反序列化不会炸。

## 它不碰什么

只清理 `raw_message` 里的 text 组件，以及 `processed_plain_text`。

被引用群友的原话（`ReplyComponent.target_message_content`）一概不碰。别人说的话，插件没有资格改。

`reply`、`at`、`image` 这些其他类型的组件同样不动。

## 两个实现细节

**两个文本视图的清除位置保持一致。** 发出去的内容和落库的内容是同一份数据的不同视图，但如果各自独立随机，就会出现发出去的文本和数据库里的文本对不上。插件用一张按出现序号惰性生成的随机判定表，「第 N 个属于是」在两个视图里杀不杀由同一次判定决定。

**任何异常都被吞掉并记日志，绝不阻塞发送。** 插件出问题最多是不生效，不能把消息卡死在半路。
