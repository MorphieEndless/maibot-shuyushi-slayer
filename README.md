# 属于是猎杀者 (Yushuyu Slayer)

> **在消息发送前按概率清除「属于是 / 了属于是」，防止模型把自己的口癖当示范越学越多。**

## 为什么需要它

### 1. 光靠 Prompt 为什么管不住口癖？
MaiBot 会把 Bot 自己之前的发言塞进历史上下文，当作示范喂回给大模型。

模型只要无意中说过一次「属于是」，接下来的每一轮请求里，上下文就多了一条**「我自己平时就是这么说话的」**真实样例。

> **上下文里的一条真实样例，比你在 Prompt 里写十遍「不要说属于是」都管用。**
> 只要模型能从历史记录里看见自己说过，这种口癖就会不断被自我强化。

### 2. 为什么挂在 `send_service.before_send`？
要从根子上解决，就得让它不要把口癖存进历史记录。

选在这个 Hook 是因为它是整个发送链路中，**唯一能同时管住「发出去的话」和「存进数据库的话」**的地方：

```text
  [模型生成回复]
        │
        ▼
┌──────────────────────────────────────────────┐
│  send_service.before_send                    │
│  ──────────────────────────────────────────  │
│  1. 按设定概率（默认 70%）挑出口癖删掉       │
│  2. 顺手修掉删词后留下的多余标点与空白       │
│  3. 保证发出去的内容和存进数据库的内容删得一致│
│  4. 如果删完只剩标点或空白，整条消息不改动   │
└──────────────────────┬───────────────────────┘
                       │
         ┌─────────────┴─────────────┐
         ▼                           ▼
[发给群友]                     [_store_sent_message 存入数据库]
 (群里看到的很干净)             (历史记录里也很干净，下轮不会被学去)
```

1. **出站最后一步**：在消息交给平台发出去之前做修改，改完后不会再被其他插件二次覆写。
2. **入库第一现场**：MaiBot 的写库操作刚好发生在这个 Hook 之后。存进数据库的是已经清理过的内容，下一轮请求拉取上下文时，自然就不会再把口癖当参考范例。

> **一个需要知道的边界**。第 2 点依赖主程序的写库时序，这属于 MaiBot 内部的链路行为，不是 SDK 对插件作出的承诺。如果将来主程序调整发送链路，把写库挪到 Hook 之前，插件会静默停止净化落库文本，但发出去的消息仍然正常清理，不会造成破坏。把 `log_kills` 保持打开，日志里每次清理都有记录，可以用来确认插件是否仍然生效。

## 它做了哪些细节处理

- **概率清理，不搞一刀切**：支持设置清除概率 `kill_ratio`（默认 `0.7`，即消灭七成）。偶尔保留一两句，语言风格看起来不会太死板。
- **发出去的和存进库的一模一样**：发出去的消息（`raw_message`）和存库的纯文本（`processed_plain_text`）是同一条消息的两份表现。插件用同一份按顺序生成的判定结果，确保**第几个口癖在两边要么都删、要么都留**，不会发出去是一套，存数据库又是另一套。
- **删空保护**：
  - 如果某段文本删完后什么都没剩下，会自动丢掉这个文本片段，避免发出空内容导致报错。
  - 如果整条消息本来有字，但删完后只剩标点符号或空格（比如原本是「？属于是」），会自动放弃修改、原样发出，不会发个莫名其妙的孤立问号。
- **绝对不碰群友的话**：只改 Bot 自己生成的文本组件。至于引用回复里群友的原话（`target_message_content`），插件一概跳过。
- **出错绝不拦路**：插件内部做了完整的错误捕获，哪怕正则写错或逻辑出问题，也只会打印一条警告日志并放行原消息，绝不会导致消息发不出去。

## 安装

### 方式一：WebUI 插件市场
在 MaiBot WebUI 的「插件市场」搜索 **「属于是猎杀者」**，点击安装即可。

### 方式二：手动安装
把仓库放到 MaiBot 的插件目录：
```bash
cd /path/to/maibot/plugins
git clone https://github.com/MorphieEndless/maibot-shuyushi-slayer.git
```
> 插件通过 `_manifest.json` 识别，文件夹叫什么名字都不影响运行。

***

## 配置

插件首次运行时会在插件目录下自动生成 `config.toml`，默认值取自 `plugin.py` 里的 `config_model`。可以在 WebUI 的插件页面直接改，也可以编辑这个文件。

仓库里的 `config.example.toml` 只是默认值的对照参考，不参与运行。

生成出来的默认配置如下。

```toml
[plugin]
config_version = "1.0.0"
enabled = true

[slayer]
enabled = true
kill_ratio = 0.7                # 清除概率：0.0 ~ 1.0，0.7 代表清理 70% 的命中词
patterns = ["了?属于是"]         # 正则表达式列表，默认把前面的「了」一起删掉
cleanup_text = true             # 删词后自动清理句首残留的标点和多余空格
guard_empty = true              # 如果删完整句话只剩标点或空白，自动放弃修改
max_kills_per_message = 0       # 单条消息最多删几处，0 表示不限制
sync_processed_text = true      # 同步清理存数据库用的纯文本（关掉则只改发出去的消息）
dry_run = false                 # 演练模式：只在日志里打印命中情况，不真正改动
log_kills = true                # 每次执行清理时在后台打印日志
only_groups = []                # 只在这些群生效，填群号字符串；留空代表所有群
skip_groups = []                # 排除这些群，在里面不生效
```

### 参数一览

| 参数 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `enabled` | `bool` | `true` | 功能总开关 |
| `kill_ratio` | `float` | `0.7` | 每个命中词被清除的概率 |
| `patterns` | `list[str]` | `["了?属于是"]` | 匹配用的正则列表，多个正则按从左到右匹配 |
| `cleanup_text` | `bool` | `true` | 清除后修掉残留的句首标点与连续空格 |
| `guard_empty` | `bool` | `true` | 避免把整句话删空；删空时自动回滚回原句 |
| `max_kills_per_message`| `int` | `0` | 每条消息最多清理几处，`0` 为不限 |
| `sync_processed_text` | `bool` | `true` | 同步清理存入数据库的文本 |
| `dry_run` | `bool` | `false` | 观察模式，打开后只记日志不改文字 |
| `log_kills` | `bool` | `true` | 清除成功时记录前后的文本变化 |
| `only_groups` | `list[str]` | `[]` | 白名单群号，留空代表所有群 |
| `skip_groups` | `list[str]` | `[]` | 黑名单群号 |

## 常用调整技巧

* **先观察命中情况**：
  把 `dry_run` 设为 `true` 跑一两天。看日志里记录的命中数和预计清除比例，觉得符合预期再正式打开。
* **清理其他口癖**：
  `patterns` 是普通的 Python 正则列表。如果 Bot 又染上了别的口癖，直接往列表里加：
  ```toml
  patterns = ["了?属于是", "可以说是", "属实是"]
  ```
* **觉得清理太频繁**：
  把 `kill_ratio` 调低到 `0.3` 或 `0.5` 即可。
